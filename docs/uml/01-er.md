## Notes

- **Multi-tenancy spine**: every tenant-scoped table carries `clinic_id`; RLS
  policies (`backend/postgres_schema.sql`) restrict rows to `auth.uid()` via
  `clinic_users`. The `uid()` helper reads the per-request GUC
  `app.current_user_id` set by the API. RLS is ENABLED but NOT FORCED (the
  table-owner connection bypasses it, keeping the unauth API working);
  enforcement lands with the router guards (spec-auth.md Q2).
- **Local auth (G6-Q1)**: `users` is the app identity table (email and/or
  phone, PBKDF2 password, hashed OTP); `clinic_users.user_id` FK now points
  at `users.id` (was Supabase `auth.users`).
- **Phase-1 EHR is transcript-only**: `calls.transcript` (JSONB) is the medical
  record; `call_embeddings` feeds pgvector similarity search (1536-dim).
- **`language_codes`** is reference data: seeds hi/en/ta/te/bn with Deepgram
  `nova-3` and per-language ElevenLabs voice IDs.
- **`payments`** (G6-Q5 wired) records intents (kind: consultation / refill /
  subscription; gateway razorpay / phonepe / cashfree / manual) with an
  `expires_at` TTL and a UNIQUE partial index on `gateway_ref` (webhook
  idempotency). The router dispatches the gateway request only when the
  gateway's env keys are present; the userless webhook writes under the
  `app.service_request` bypass.
- **`notifications`** (G6-Q8 wired) is the WhatsApp-first delivery trail:
  per-kind/per-language templates in `app/services/notifications.py`, channel
  status (queued / sent / failed) per row, UNIQUE partial index on
  `provider_ref` (delivery idempotency), and the `notifications_send` policy
  (membership OR `app.service_request` bypass). The payment-create hook writes
  payment_link rows for link/UPI intents — a non-fatal recorded side effect.
  Rows feed the DPDP audit (G6-Q2, spec-dpdp-q2.md).
- **`compliance_events`** (G6-Q2 wired) is the DPDP event record: data_breach /
  consent_withdrawal / gdpr_request rows with `notification_deadline` =
  detected_at + 72h (DPDP Act 2023) computed at insert by
  `services/compliance.py`, status lifecycle open → reported → closed
  (→ reported stamps `reported_at`), RLS `compliance_manage` (membership OR
  `app.service_request`). **`calls.recording_consent`** (unknown/granted/
  denied, default unknown) is the per-call DPDP flag the LiveKit egress gate
  reads; retention (365/365/180/2190 days per kind, `services/retention.py`)
  is enforced by `postgres.purge_expired` from the Docker/CI cron.
- **G6-Q9 analytics adds no entities** (spec-kpis-q9.md Q3=A1): the seven MVP
  KPIs are read-only aggregates over `calls` (volume/triage/language/
  resolution), `appointments` (no-show), `payments` (revenue) and
  `notifications` (delivery success), computed live per request behind
  `/api/analytics`; RLS on those tables scopes every query to the clinic.
